# PAYMENTS_AND_DELIVERY.md — Cinematic Mode за Telegram Stars

## Состояние после очистки — 22 ноября 2026

Старые история, изображения, карта и фильм удалены из рабочего проекта. С 24 ноября каталог содержит новую главу в трёх частях без фотографий, с заглушками для иллюстраций. Создание новых счетов за отсутствующую карту недоступно. Существующие платежи и права пользователей сохранены. Ниже описан план будущего продукта; он не означает, что фильм уже существует.

## Модель продукта

- Бесплатно: опубликованный текст в трёх частях; вместо будущих изображений пока заглушки.
- Платно: видео «Глава 1 / Cinematic Mode», 3 части, повторный просмотр после покупки.
- Рекомендуемая **гипотеза**, а не установленная цена: `39 XTR` за всю первую главу. Цена на стороне сервера/конфига.
- Текущая карта маршрута за `15 XTR` — **отдельное** право и товар, существующую покупку не ломать.
- Никакого прямого TON-чекаута за цифровой контент **внутри Telegram Mini App**. Официальная документация: https://core.telegram.org/bots/payments-stars и https://telegram.org/tos/bot-developers.

## Предлагаемый data model

```text
catalog_products
  sku: cinematic_chapter_1 | route_map_1
  currency: XTR
  price_stars: integer
  active: boolean

payment_events
  telegram_payment_charge_id UNIQUE
  telegram_user_id
  sku
  amount_xtr
  status
  received_at

entitlements
  telegram_user_id
  sku
  status: active | revoked
  granted_at
  UNIQUE(telegram_user_id, sku)
```

Не переносить production на файловый JSON при денежной нагрузке без плана транзакционности, конкуренции и бэкапов; применить транзакционную БД.

## Безопасная последовательность оплаты

1. Клиент с подтверждённым Telegram initData запрашивает SKU через сервер.
2. Сервер проверяет SKU/сумму и выдаёт `createInvoiceLink` / Star-инвойс `XTR`.
3. Бот проверяет `pre_checkout_query`: товар, сумму, пользователя, платёжное состояние; ответ в отведённое Telegram время.
4. Доверять **только** Telegram `successful_payment`, сверять `telegram_payment_charge_id`, payload, сумму, user ID; атомарно записывать платеж и entitlement с защитой от повторной доставки событий.
5. Клиент перечитывает право с сервера. Не открывать фильм лишь потому, что `openInvoice()` вернул `paid`.
6. Защищённое видео выдавать лишь по валидному entitlement, через authenticated HTTP range stream или короткоживущую signed URL приватного storage. Тестировать повторный GET, Range/206, cache policy, TTL, отсутствие indexable public URL.
7. Реализовать `/paysupport` или аналогичный доступный путь поддержки, refund workflow и отзыв доступа при реальном возврате там, где применимо; операции возврата idempotent и аудитируемы.

## Защита видео

- `public/`, `docs/`, GitHub Pages и публичный репозиторий НЕ являются безопасным платным хранилищем.
- Приватный storage (S3-compatible) + backend auth + временная подписанная ссылка предпочтительнее тяжёлой выдачи видео из одного Node-инстанса. Проверить стоимость и требования к инфраструктуре.
- Ссылки нельзя считать DRM. Запись экрана и сохранение уже воспроизведённых байтов технически возможны; обещать «нельзя скачать» недопустимо.
- В статической Pages-версии: рекламная карточка режима/трейлер/пробная сцена, но не оплачиваемый видеофайл.

## Тесты и запуск

- Оплата отменена, не прошла, повторный webhook/update, неверный SKU, другой пользователь, некорректная сумма, refund, восстановление на другом устройстве, защищённые Range, истекшая signed URL.
- Мобильная навигация и субтитры внутри реального Telegram WebView.
- Публикация только после готовности видео, HTTPS, серверного хранения и поддерживаемых правил Star checkout.
