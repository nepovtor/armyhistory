# HIStory

**HIStory** — Telegram Mini App с реальными историями, разделёнными на главы и части. Начальная история: «Три года до дома», глава 1 «Начало службы», часть 1 «Дорога в Севастополь» (19–21 ноября). Вдохновлено рассказом очевидца: исторические факты не переписываются, читательские развилки меняют только ракурс.

## Что готово

- 9 последовательных сцен, выбор ракурса, экран завершения части.
- Каталог, список глав и частей, дневник, шаг назад, сохранение прогресса.
- Адаптивный интерфейс с авторскими SVG-иллюстрациями.
- Node.js сервер с проверкой Telegram `initData` по HMAC и файловым сохранением.
- Telegram-бот: `/start`, меню с кнопкой Mini App, `/help`.
- **Отдельная автономная демоверсия** для GitHub Pages, сохраняющая прогресс в `localStorage` браузера.

## Смотреть в браузере

После публикации GitHub Pages: `https://nepovtor.github.io/HIStory/`.

> GitHub Pages показывает автономную демоверсию, в том числе **внутри Telegram**, если указать URL в BotFather. Прогресс хранится локально в WebView. Чтобы синхронизировать его между устройствами и проверять Telegram `initData` на сервере, потребуется отдельный Node.js HTTPS-хостинг. GitHub Pages **не запускает** сервер и бота.

## Локальный запуск

Нужен Node.js **20+**, установки зависимостей нет.

```bash
npm run dev
# http://localhost:3000
```

```bash
npm test              # 10 тестов
npm run build:pages   # docs/index.html — статическая демоверсия
npm run build:demo    # ../HIStory-demo.html — автономный HTML
```

В режиме разработки прогресс хранится в `data/progress.json` (исключено из Git). **Не включать `DEMO_MODE=1` на публичном сервере.**

## Запуск GitHub Pages

Репозиторий должен быть **публичным**. Workflow `.github/workflows/pages.yml` собирает демоверсию, прогоняет тесты и отправляет `docs/` на Pages. В GitHub открой **Settings → Pages → Build and deployment → Source: GitHub Actions**. Workflow запустится после push в `main`, либо вручную через **Actions → Deploy HIStory demo → Run workflow**. Проверь адрес, который GitHub покажет в Pages.

Если автоматическая публикация недоступна, в **Settings → Pages** выбери **Deploy from a branch → main → /docs**, затем сохрани. В `docs/index.html` уже включена автономная версия.

## Подключить демоверсию к Telegram без сервера

1. Создать бота в [@BotFather](https://t.me/BotFather) (`/newbot`).
2. Когда GitHub Pages заработает, в BotFather выбрать `/setmenubutton`, своего бота и указать название кнопки `Открыть HIStory` и URL `https://nepovtor.github.io/HIStory/`.
3. Открыть бот, нажать кнопку меню. Это будет работающая статическая версия игры внутри Telegram, с локальным прогрессом.

## Полный Telegram-бот с серверным прогрессом

1. Создать бота у [@BotFather](https://t.me/BotFather) и получить `BOT_TOKEN`.
2. Задеплоить Node.js сервер `npm start` на внешнем HTTPS-хостинге с **постоянным диском**, Node.js 20+.
3. Создать `.env` по `.env.example` на хосте, заполнить `BOT_TOKEN`, `APP_URL=https://your-domain.example`, `NODE_ENV=production`, `DEMO_MODE=0`, `DATA_DIR=/persistent/history`.
4. Запустить один инстанс бота: он настроит кнопку меню и ответит на `/start`.
5. Проверить авторизацию и прогресс на настоящем Telegram-клиенте.

Не коммитить `.env` и токен. Для production рекомендуется БД вместо JSON и резервное копирование. Telegram требует HTTPS для Mini App. GitHub Pages не заменяет backend.

## Структура

- `server/content.mjs` — истории, главы, части и сцены.
- `server/engine.mjs` — сюжетная логика и прогресс.
- `server/index.mjs` — HTTP/API и статика.
- `server/auth.mjs` — проверка подписи `initData`.
- `server/bot.mjs` — Telegram-бот.
- `public/` — клиентское приложение и SVG-графика.
- `tools/build-demo.mjs` — генератор отдельной офлайн-версии.
- `docs/index.html` — заранее собранная демоверсия для GitHub Pages.
- `docs/source-story-chapter-1-part-1.md` — исходный текст воспоминаний.
- `tests/` — автоматические тесты.

## Добавление частей

В `server/content.mjs` добавь новые сцены и связи `next`, у следующей части поставь `published: true`, `start` и `sceneCount`. Внутри главы можно размещать много частей. Содержимое частей 2 и 3 намеренно закрыто до получения продолжения текста.

## Ограничения

- Реальный bot token, URL и домен не включены; Telegram-бот не работает только от загрузки на GitHub.
- Автономное демо не синхронизирует прогресс между устройствами.
- Год событий в тексте пока не установлен, не придуман.
- Исходные биографические данные взяты только из предоставленных воспоминаний.


## Визуальная версия «Подводный флот. 1990–1993»

Интерфейс переработан под военно-морскую графическую новеллу: тёмно-синий фон, красная навигация, бумажные панели и комикс-иллюстрации.
`public/assets/*.webp` — художественные иллюстрации, а не документальные фотографии отца или достоверное изображение конкретной подводной лодки.

**Достоверность.** Уточнены годы службы (1990–1993) и тип подводной лодки (атомная). Модель, бортовой номер и подробности будущих эпизодов не выдумываются. Исходные воспоминания хранятся в `docs/source-story-chapter-1-part-1.md`.

Для пересборки публикации: `npm run build:pages`, результат — `docs/index.html` (все художественные изображения встроены, режим чтения локальный).
